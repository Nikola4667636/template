# Trip Service (TripGo) — Лабораторная работа 1

Сервис управления жизненным циклом поездок для платформы такси TripGo.

### 1. Поднятие инфраструктуры

```
tripgoctl cluster start       # если кластер еще не запущен
tripgoctl environment start   # поднять PostgreSQL и сгенерировать .env
```
### 2. Применение миграций
```
make migrate
```
### 3. Запуск сервиса
```
make run
```
Сервис поднимется на порту, указанном в .env (по умолчанию http://localhost:8080).

## Переменные окружения

Конфигурация считывается из окружения / файла .env:

Переменная | Описание 
:--- | :--- 
HTTP_ADDR | Адрес и порт HTTP-сервера (напр., :8080) 
DATABASE_URL | Строка подключения к PostgreSQL 
DATABASE_MAX_CONNS | Максимальное число соединений в пуле 
DATABASE_MIN_CONNS | Минимальное число соединений в пуле 
DATABASE_CONNECT_TIMEOUT | Таймаут подключения к БД 
DATABASE_QUERY_TIMEOUT | Таймаут выполнения SQL-запроса 
DATABASE_MAX_CONN_LIFETIME | Максимальное время жизни соединения 
LOG_LEVEL | Уровень логирования (debug, info, warn, error) 
SHUTDOWN_TIMEOUT | Бюджет времени на graceful shutdown (напр., 5s)
HTTP_READ_TIMEOUT | Таймаут на полное чтение запроса
HTTP_READ_HEADER_TIMEOUT | Таймаут на чтение только заголовков запроса
HTTP_WRITE_TIMEOUT=10s | Таймаут на запись ответа клиенту
HTTP_IDLE_TIMEOUT=120s | Таймаут, в течение которого keep-alive соединение может простаивать без активных запросов

## Принятые решения и архитектура

### 1. Уровень изоляции транзакций по умолчанию
Для TxManager выбран уровень изоляции Read Committed.
Почему: Для операций создания поездки и записи в журнал статусов этого уровня достаточно в сочетании со строгими ограничениями схемы PostgreSQL (уникальный индекс). Это обеспечивает высокую производительность пула соединений без избыточного оверхеда Serializable.

### 2. Менеджер транзакций (TxManager)
Реализован интерфейс TxManager с методом Do(ctx, fn).
Объект транзакции pgx.Tx внедряется непосредственно в context.Context.
Репозиторий прозрачно проверяет наличие активной транзакции в контексте: если она есть, запросы выполняются внутри неё; если нет — напрямую через pgxpool.Pool.
Вложенные вызовы Do переиспользуют существующую транзакцию из контекста без открытия новой.
При ошибке или панике внутри fn происходит автоматический ROLLBACK, гарантирующий атомарность записи в таблицы trips и trip_status_history.

### 3. Запрет двух активных поездок у одного водителя
Ограничение реализовано на уровне базы данных с помощью уникального частичного индекса (Partial Unique Index) в PostgreSQL:

CREATE UNIQUE INDEX idx_trips_driver_active 
ON trips (driver_id) 
WHERE status = 'active';

При попытке создания второй активной поездки PostgreSQL возвращает ошибку 23505 (unique_violation). Сервис перехватывает её на уровне репозитория и трансформирует в доменную ошибку driver_busy (409 Conflict в HTTP API). Это гарантирует строгую защиту от race condition при параллельных запросах.


## Команды Makefile

* make generate — генерация Go-кода по контракту OpenAPI (oapi-codegen).
